# Architecture rules
- Render one responsive homepage hero; initial counters contain their final values, browser-only animations respect reduced motion and the build-time prerender marker, and FAQ answers stay mounted while collapsed.
- Keep initial reveal content visible and hotspot positions at CSS fallbacks; only mount effects animate or measure, and __PRERENDER__ freezes them so snapshots preserve initial root markup.
- Validate every serialized snapshot and compare JS/no-JS visible main text at a 2% word-edit threshold; failed routes block export rather than silently shipping incomplete pages.
- Production export uses build-time Chromium rendering of complete pages with React 18, Vite 5 and TypeScript; Serverprofis serves HTML without a persistent Node server or runtime SSR.
- Keep build:dev Vite-only for Lovable preview builds and their injected config; production build retains mandatory Chromium prerendering and must not silently fall back to SPA output.
- SEOHead and the static export use the shared route catalogue and metadata writer for identical route-specific head tags, self-referencing canonical URLs and removal of obsolete metadata; browser navigation and exported pages must not drift.
- Sitemaps include only unique canonical indexable routes and use only page-specific known modification dates; never invent build-time or year-derived timestamps.
- Keep source-based news articles in dedicated pages, with shared article metadata consumed by the news overview and SEO route catalogue to avoid date and URL drift.
- Consolidate service and maintenance content under /managed-services; permanently redirect /service-wartung to the hub to preserve inbound links without duplicate pages.
- Keep CARE model conditions in a shared editorial data catalogue consumed by the interactive comparison and service schemas, to prevent contract drift.
- Keep service Whitepapers private as editorial sources; never ship their PDFs in public downloads.
- Keep customer-reference metadata, dates and descriptive image texts in the shared project catalogue so cards, details and schemas agree.
- Keep reference product links and manufacturer-verified facts in the shared project catalogue; render them optionally on reference pages to avoid duplicated product content.
- Homepage carousels consume the complete project catalogue and shared news feed; use one responsive carousel with viewport-aware autoplay and pause controls to keep mobile content compact and current.
- Store reference-specific cropped photo variants in the shared project catalogue; use the reusable slideshow for fading detail images without modifying the original customer photos.
- Customer media for external FTP hosting must have optimized static public copies alongside asset provenance pointers, because Serverprofis cannot serve Lovable-relative asset URLs.
- Regional pages render immutable service-specific editorial content from per-city JSON; sources and review notes never enter public markup or bundles, and export validates static content plus a 20% identical-sentence threshold for introductions and requirements.
- Regional metadata reads the required service-specific description field verbatim from each city JSON; missing or invalid descriptions throw during catalogue loading and block builds, with no derived fallback.
- Strip private regional JSON fields before Vite JSON transformation so research and review notes stay source-only, including in browser assets.
- Manufacturer certification claims come only from src/data/certifications.ts; unconfirmed vendors are labeled "Erfahrung mit", never "zertifiziert".
